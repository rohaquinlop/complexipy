    AI Agent Workflows¶

    Coding agents such as Claude Code and Codex CLI write code in a loop: edit files, run tools, and continue from the output. Cognitive complexity measures how hard that code is to review, and a function over the limit is cheapest to fix while the agent still has the file in context, if something tells the agent about it.

    Hooks are commands an agent runs at lifecycle events. A hook that runs complexipy puts the analysis in the same turn, before a human reads the diff. This page shows two hooks for both agents: one after each file edit, one when the agent tries to finish.

    What the hooks use from complexipy¶

    complexipy exits with status 1 when a function is above max-complexity-allowed, and 0 when the code passes. A hook maps that exit code to the agent's feedback protocol, so the hook itself stays small.

    The recipes check the diff instead of the whole repository:

    • complexipy <file> --diff HEAD checks the edited file on each edit.
    • complexipy . --diff main checks the branch when the turn ends.

    Each hook passes the report to the agent as its feedback. --failed --plain --suggest-refactors keeps it short: one path:line function complexity line per function over the limit, and one line per refactor plan with its rule id, title, and reduction:

    complexipy src/app.py --diff HEAD --failed --plain --suggest-refactors --max-complexity-allowed 15

    src/app.py:3 nested 6
  C007 Merge 3 nested if statements (-4)

    The diff table follows, and so does the list of functions that an ignore comment the change added now hides, so an agent cannot pass the check by adding # complexipy: ignore.

    The scripts are POSIX sh and expect complexipy on the PATH. They work in git repositories, because --diff needs a reference to compare against.

    Both hooks compare with a git reference: the edit hook checks the uncommitted changes of the file the agent edited, and the Stop hook checks the whole branch against main. Start the agent from a clean tree, or commit or stash your own work, so the feedback is about the agent's changes.

    The edit hook¶

    Save this script in the hook directory of your agent and make it executable:

    #!/bin/sh
limit=${COMPLEXIPY_MAX_COMPLEXITY:-15}
ref=${COMPLEXIPY_EDIT_DIFF_REF:-HEAD}
file=$(sed -n 's/.*"file_path"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' | head -n 1)
case "$file" in
    "") target=. ;;
    *.py) target=$file ;;
    *) exit 0 ;;
esac
root=$(git rev-parse --show-toplevel 2>/dev/null) || exit 0
cd "$root" || exit 0
if ! git rev-parse --verify --quiet "$ref^{commit}" >/dev/null; then
    printf '%s\n' "complexipy hook: the git reference '$ref' does not exist." >&2
    exit 1
fi
report=$(complexipy "$target" --diff "$ref" --failed --plain --suggest-refactors \
    --max-complexity-allowed "$limit" --color no 2>&1)
status=$?
if [ "$status" -eq 0 ]; then
    exit 0
fi
if [ "$status" -ne 1 ]; then
    printf '%s\n' "complexipy could not check the edit (exit $status):" "$report" >&2
    exit 1
fi
printf '%s\n' "complexipy: the edit adds or worsens a function above the cognitive complexity limit of $limit." "$report" "Refactor the functions listed above." >&2
exit 2

    The script reads tool_input.file_path from the hook input on stdin, skips a file that is not Python, and checks only that file. When the input names no file, as with a Codex apply_patch edit, it checks every uncommitted change. Exit status 2 is the feedback signal for both agents: Claude Code shows the stderr text to the model, and Codex CLI replaces the tool result with it.

    The end-of-turn hook¶

    Save this script next to the edit hook:

    #!/bin/sh
limit=${COMPLEXIPY_MAX_COMPLEXITY:-15}
ref=${COMPLEXIPY_DIFF_REF:-main}
if grep -Eq '"stop_hook_active"[[:space:]]*:[[:space:]]*true'; then
    exit 0
fi
root=$(git rev-parse --show-toplevel 2>/dev/null) || exit 0
cd "$root" || exit 0
if ! git rev-parse --verify --quiet "$ref^{commit}" >/dev/null; then
    printf '%s\n' "complexipy hook: the git reference '$ref' does not exist." >&2
    exit 1
fi
report=$(complexipy . --diff "$ref" --failed --plain --suggest-refactors \
    --max-complexity-allowed "$limit" --color no 2>&1)
status=$?
if [ "$status" -eq 0 ]; then
    exit 0
fi
if [ "$status" -ne 1 ]; then
    printf '%s\n' "complexipy could not check the branch (exit $status):" "$report" >&2
    exit 1
fi
printf '%s\n' "complexipy: the branch adds or worsens a function above the cognitive complexity limit of $limit." "$report" "Refactor the functions listed above before you finish." >&2
exit 2

    It compares the branch with main and runs again whenever the agent tries to stop. A failing status sends the agent back to work with the message; a passing one lets the turn end. The script reads stop_hook_active, so it blocks at most once per turn. Set COMPLEXIPY_DIFF_REF when your base branch is not main, and COMPLEXIPY_MAX_COMPLEXITY when you use a different limit. The edit hook takes its own reference from COMPLEXIPY_EDIT_DIFF_REF (default HEAD), which helps when the agent commits after each edit.

    A Stop hook fires at the end of every response, not only when the task is complete, so the check runs on each turn and blocks when the branch adds or worsens a function above the limit.

    Both agents pass stop_hook_active in the hook input. The script exits 0 while that flag is true, which keeps a Stop hook from blocking forever. Claude Code also cuts a Stop hook after eight consecutive blocks.

    Claude Code¶

    Copy both scripts to .claude/hooks/ in the repository and make them executable:

    chmod +x .claude/hooks/complexipy-edit.sh .claude/hooks/complexipy-stop.sh

    Add both events to .claude/settings.json. If the file already has a hooks object, add these entries as siblings of the existing event keys:

    {
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|MultiEdit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/complexipy-edit.sh"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/complexipy-stop.sh",
            "timeout": 120
          }
        ]
      }
    ]
  }
}

    Claude Code normally reloads hooks when the settings file changes; restart the session if a new hook does not appear. Run /hooks to confirm both appear under PostToolUse and Stop.

    Claude Code runs project hooks only after you trust the workspace.

    To test a hook without an agent turn, pipe the input the event sends on stdin and check the exit code:

    echo '{"hook_event_name":"Stop","stop_hook_active":false}' | .claude/hooks/complexipy-stop.sh

    Exit 0 lets the turn end, and exit 2 blocks the stop and passes the message to the agent. See the Claude Code hooks reference for the event fields and the exit code rules, and the hooks guide for more examples.

    Codex CLI¶

    Copy both scripts to .codex/hooks/, then create .codex/hooks.json:

    {
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "apply_patch|Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "sh \"$(git rev-parse --show-toplevel)/.codex/hooks/complexipy-edit.sh\"",
            "timeout": 120,
            "statusMessage": "Checking cognitive complexity"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "sh \"$(git rev-parse --show-toplevel)/.codex/hooks/complexipy-stop.sh\"",
            "timeout": 120,
            "statusMessage": "Checking cognitive complexity"
          }
        ]
      }
    ]
  }
}

    The commands resolve the scripts from the git root because Codex can start in a subdirectory. Codex runs a project hook only after you trust the project .codex layer and review the hook with /hooks, and it asks again when the hook changes. The same hooks can be declared inline in .codex/config.toml under [[hooks.PostToolUse]] and [[hooks.Stop]] if you prefer one file. See the Codex hooks reference for the full schema and the trust rules.

    Recipes without hooks¶

    The same verdict works outside the agent loop:

    • Gate the branch in pre-commit or CI with complexipy . --diff main --max-complexity-allowed 15; see CI/CD.
    • Ask for a plan with complexipy <path> --suggest-refactors, review the patch with complexipy <path> --fix --dry-run, and apply it with --fix.
    • Record the rule in the instruction file the agent reads (AGENTS.md or CLAUDE.md): "Keep every function at or below 15 cognitive complexity. Before you finish, run complexipy . --diff main --max-complexity-allowed 15 and refactor anything it flags."
    • Point the editor at the language server when the agent reads diagnostics; see Editor Integration.

    Notes¶

    • The path:line form, the refactor plan lines in --plain, and the list of ignore comments a change adds need 9.0.0 or newer. With 8.3.0, the hooks give the same exit codes, and the feedback shows path function complexity lines and the diff table.
    • When a tool needs structured data instead of text, --output-format json --output - (9.0.0 or newer) writes the report to stdout. Each entry carries line_start, line_end, and line_complexities, the lines that add to the score.
    • The hooks treat exit 1 as a limit breach, and complexipy also exits 1 for some configuration errors. When the feedback does not match a function in the diff, read the message at the end of the feedback.
    • --diff needs Git 2.30 or newer. Each hook checks first that its git reference exists. When it does not, for example when the default branch is master, the hook exits 1 with a message that names the reference; set COMPLEXIPY_DIFF_REF or COMPLEXIPY_EDIT_DIFF_REF to a reference that exists.
    • Hooks run with your permissions. Review the scripts before you commit them to a repository, like any other command a tool executes for you.
    • The scripts need a POSIX shell. On Windows, install Git for Windows, which provides sh, and make sure the agent finds it on the PATH.
    • Hook formats change between agent releases. The examples follow the references linked above, and the scripts need no change when the configuration schema moves.
